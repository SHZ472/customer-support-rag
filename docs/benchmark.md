# 课程版短测记录

2026-11-10，在同一台 Windows 主机运行 Locust 和 Docker Compose 客服服务。同一 API 镜像依次将查询向量缓存设为 0 和 256，使用相同的请求与预热过程。

| 条件 | 缓存关闭 | 缓存开启 |
| --- | ---: | ---: |
| 虚拟用户 | 4 | 4 |
| 配置时长 | 20 s | 20 s |
| 实测请求 | 1732 | 10440 |
| 失败数 | 0 | 0 |
| 成功 QPS | 88.95 | 538.25 |
| P99 | 87 ms | 13 ms |

每个虚拟用户循环两道精确查询、三道 FAQ、一道资料不足的问题。预热在统计窗口之外。验证检查 HTTP 状态、业务路由、来源和答案要点。缓存开启时，四个需要 FAQ 检索的问题都在预热中生成过向量。成功 QPS 用成功请求数除以测量窗口，P99 来自 Locust 的响应耗时分布。

这组数据来自课程版服务，整理后的展示版另用仓库验收脚本复验。首次出现的问题仍有 BGE 编码开销。真实流量的请求分布、重复率、持续容量和自动解决率尚待测量。
